NooDS‑Wii ARM→PPC JIT — Root‑cause report

Symptoms: NDS games hang on white screen (ARM9 spinning at 020001A4/020001B4, ARM7 at 03800728); GBA games show the boot logo then a black screen. Both are explained by the miscompilations listed below. A complete corrected jit_ppc.cpp is at the bottom of this page (download button).

Bugs found (ordered by impact)

CRITICAL C and V flags were always written as 0

setC_xer, setC_imm and setV_add/sub used LSB‑numbered bit positions in rlwinm masks, but PowerPC rlwinm masks are IBM/MSB‑numbered. rlwinm(TA,TA,0,29,29) keeps 0x00000004, not XER.CA (0x20000000 = IBM bit 2). Likewise V used mask (28,28) = 0x8 instead of (3,3) = 0x10000000. Every CMP/SUBS/ADDS followed by BCS/BCC/BHI/BLS/BGE/BLT/BGT/BLE was wrong — countdown loops using subs; bcs spin forever, which is exactly the two‑block loop your ARM9 is stuck in.

CRITICAL setNZ / setC_xer clobbered the operands needed for V

Both helpers used TA (r3) as scratch, but every arithmetic emitter passed TA as an operand to the subsequent setV_* call (and emitDP reloaded op2 into TA right before). V was computed from the Z‑mask value. Fixed by giving the flag helpers a dedicated scratch register TS (r10) and a dedicated discard register TR (r12) for TST/TEQ/CMP/CMN results (the old code wrote TST results into TC, destroying the shifter carry‑out).

CRITICAL Thumb dispatcher was off by one format group

In dispThumb: h=1 (ASR imm / ADD‑SUB reg‑imm3) went to the MOV/CMP/ADD/SUB‑imm8 emitter; h=2 (MOV/CMP imm8) went to the ALU/hi‑reg/LDR‑PC emitter; h=3 (ADD/SUB imm8) and h=4 (ALU, hi‑reg, LDR PC‑rel) went to the load/store‑register emitter. Nearly every Thumb instruction was silently miscompiled without a fallback log — which is why the GBA (almost entirely Thumb after the logo) dies instantly.

CRITICAL SUB SP,#imm compiled as ADD SP,#imm

emitT_addSpPc tested (op>>8)&0xF == 1 for SUB, but the sign bit is bit 7 (0xB080..0xB0FF). Every function prologue that reserves stack space corrupted the stack.

HIGH Thumb hi‑register ops with PC

BLX Rm (0x4780) was treated as BX and never set LR. ADD PC,Rs / MOV PC,Rs went through BX semantics and switched to ARM whenever the value was even; on ARMv4/v5 they stay in Thumb. BX PC now aligns to 4.

HIGH MSR/MRS decoding

MSR CPSR_x, #imm (0x0320F000) was never routed to emitMrsMsr (bit 25 set), fell into emitDP as TEQ with S=0 and became a NOP. MRS Rd,SPSR matched the CPSR pattern because bit 22 was masked out. The register‑form MSR matched the immediate path. All fixed; anything touching mode/I/F bits still falls back to the interpreter (which is required so setCpsr() can schedule interrupts).

HIGH ADC/SBC/RSC carry priming ordered before the shifter

primeCarry ran before emitShifter, but srawi/sraw/subfic in the shifter overwrite XER.CA. Also, register‑specified shifts with S never updated C, and RRX with dst==TA clobbered itself. Register shifts now go through a small C helper that implements exact ARM shift/carry semantics for any amount.

HIGH ARMv4 (ARM7/GBA) LDM PC / POP PC must not switch to Thumb

Both block‑transfer helpers used ARMv5 interworking semantics for all CPUs. On the ARM7, POP {pc} stays in Thumb and LDM {..,pc} stays in ARM regardless of bit 0. GBA code that pushes an even address and pops into PC crashed.

MEDIUM Run loop & timing didn't follow NooDS semantics

The old runner executed exactly 32 iterations and returned, charged cycles as max(c0, 2·c1), ran the ARM7 at the same block rate as the ARM9, and its local cycle targets would break across RESET_CYCLES. It now mirrors Interpreter::runNdsFrame: run until core.running is cleared, per‑CPU cycle targets (ARM7 ×2), jump straight to the next event when both CPUs are halted, and re‑base targets when the cycle counter is reset. Per‑instruction costs are approximated by class (ALU 1, load/store 2, LDM/STM 1+n, branch 3) and the interpreter's return value is used for fallback instructions.

MEDIUM Misc correctness
  • LDR now rotates misaligned words like NooDS' ldrOf; ARM7 LDRH rotates on odd addresses, LDRSH on an odd address loads a signed byte.
  • Post‑indexed LDR Rd,[Rn],#x with Rd==Rn no longer overwrites the loaded value; STM with Rn in the list stores the written‑back base when Rn isn't first.
  • BX target for ARM mode is aligned to 4, not 2.
  • Block cache is keyed by CPU as well as PC (ARM7 binaries often live in main RAM; a block bakes in its Interpreter*).
  • invalidateJitRange keeps a per‑4 KB page block counter, so the common no‑blocks case is O(1) instead of a 4096‑entry scan per write.
  • Per‑block word budget raised (1024) with a 320‑word margin so conditional LDM‑PC blocks can't overflow and fail to compile every time.
  • 0‑instruction blocks (fallback at the first instruction) skip the JIT round‑trip and go straight to the interpreter.

Things to verify outside jit_ppc.cpp

  • Interpreter::jitRunOpcode() should simply return runOpcode(); — the new runner uses its return value as the cycle cost of fallback instructions (clamped to ≥1 if it returns 0).
  • Interpreter::unhalt() / halt() must call core->updateRun() (your updateRun selects runCoreNone when both CPUs halt, so the unhalt must switch back). The NooDS originals of sendInterrupt()/interrupt() clear halted directly — make sure your versions go through unhalt(0).
  • Memory::write, DMA and cartridge transfers into RAM/WRAM/VRAM/ITCM should call core->invalidateJitPage(addr). With the page counter this is now cheap enough to call on every store.
  • HLE BIOS IRQ return works unchanged: the return address fetches the reserved opcode 0xFF000000 (cond=15), which the JIT always hands to the interpreter (handleReserved → finishHleIrq).
  • No change is needed in core.cpp, jit_ppc.h or jit_trampoline.S.
