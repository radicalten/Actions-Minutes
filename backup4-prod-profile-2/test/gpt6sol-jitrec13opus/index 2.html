01 / Root cause

Two deterministic translation bugs

The trace shows repeated PCs and rising JIT counts, not a crash. That is consistent with an emulated loop waiting on state that never becomes correct. These code paths can produce that behavior directly.

01

Thumb instruction groups are shifted

In dispThumb, 0x2000-0x3FFF is sent to the wrong emitters, and 0x4000 is decoded as memory access. GBA boot transitions and ARM7 game code use these instructions constantly.

02

Flag updates overwrite operands

setNZ() and setC_xer() overwrite TA, but later overflow calculations still use TA. In emitDP, test instructions also place their result in TC, overwriting the shifter carry stored there. Conditional branches can then take the wrong path.

03

Execution accounting and state changes need a second pass

A fallback after translated instructions charges only one instruction. The NDS runner continues its 32-iteration loop even if a scheduler event changes to GBA mode. Also, blocks are cached by PC and Thumb state but not CPU identity.

03 / Edit jit_ppc.cpp

Targeted source fixes

These are replacement excerpts, not a claim that your Wii build has been patched. The C++ project files were not available in this workspace.

Replace the switch in dispThumb. The top nibble, not the previous misaligned group, selects each Thumb instruction family.

switch (h) {
    case 0x0:
        return emitT_shifts(ctx, op);
    case 0x1:
        if ((op & 0xF800) == 0x1800)
            return emitT_addSub3(ctx, op);
        return emitT_shifts(ctx, op);
    case 0x2: case 0x3:
        return emitT_imm8(ctx, op);
    case 0x4: {
        uint8_t group = (op >> 10) & 3;
        if (group == 0) return emitT_alu(ctx, op);
        if (group == 1) return emitT_hiReg(ctx, op, curPC);
        return emitT_ldrPc(ctx, op, curPC);
    }
    case 0x5: return emitT_memReg(ctx, op);
    case 0x6: case 0x7: case 0x8:
        return emitT_memImm(ctx, op);
    case 0x9: return emitT_spLoad(ctx, op, curPC);
    case 0xA: return emitT_addSpPc(ctx, op, curPC);
    case 0xB:
        if (((op >> 8) & 0xF) <= 1)
            return emitT_addSpPc(ctx, op, curPC);
        if (((op >> 9) & 7) == 2 || ((op >> 9) & 7) == 6)
            return emitT_pushPop(ctx, op, curPC);
        return false;
    case 0xC: return emitT_ldmStm(ctx, op);
    case 0xD: case 0xE: return emitT_branch(ctx, op, curPC);
    default: return false;
}

Important: 0x1800 is the add/subtract group; 0x1000 is still a shift. Check individual Thumb emitters against interpreter results after fixing dispatch.

Replace these two helpers. Use TE as scratch so TA survives until the overflow calculation; then change the test-result register in emitDP.

static void setNZ(Ctx& ctx, uint8_t r) {
    ctx.E(ppc_rlwinm(RCPSR, RCPSR, 0, 2, 31));
    ctx.E(ppc_rlwimi(RCPSR, r, 0, 0, 0));
    ctx.E(ppc_cmpi(6, r, 0));
    ctx.E(ppc_mfcr(TE));
    ctx.E(ppc_rlwinm(TE, TE, 25, 1, 1));
    ctx.E(ppc_or(RCPSR, RCPSR, TE));
}

static void setC_xer(Ctx& ctx) {
    ctx.E(ppc_mfxer(TE));
    ctx.E(ppc_rlwinm(TE, TE, 0, 29, 29));
    ctx.E(ppc_rlwinm(RCPSR, RCPSR, 0, 3, 1));
    ctx.E(ppc_or(RCPSR, RCPSR, TE));
}

Also review ADC/SBC/RSC overflow with carry-in, and Thumb shift-by-register carry semantics. These snippets correct the clobber, not every flag edge case.

Cache key

Include CPU identity in JitBlock lookup or use separate ARM9/ARM7 caches. The same PC can map to different code on the two CPUs. Invalidate every block whose covered instruction range intersects a write, not just armPC + 32 for Thumb and ARM alike.

PC write

emitBX_target always clears only bit 0. For an ARM destination, also clear bit 1. For Thumb MOV PC/ADD PC, do not treat the write like BX: those operations should not change the T bit.

Scheduling

Count executed instructions rather than compiled instructions, especially conditional exits and interpreter fallbacks. Stop runJitNds immediately if an event enters GBA mode. The interpreter runner for the GBA fallback must run CPU 1, not runCoreSingle<true,0>.

Safer bring-up

Temporarily use one translated instruction per block, compare registers/CPSR/PC and memory side effects against the interpreter, then raise the block length. Running more blocks faster will not correct a bad translation.

04 / Verify on hardware

A test that can prove progress

First confirm the same ROM boots with JIT disabled. Then compare one instruction at a time on both CPUs, including CPSR and scheduler time. A changed screen alone is not enough evidence of correctness.

  1. Disable JIT and check the NDS and GBA baselines on the same BIOS, ROMs, and save files.
  2. Apply the Thumb dispatch fix; log the first PC/opcode where JIT and interpreter register states diverge.
  3. Apply the flag fix; compare r0-r15, CPSR N/Z/C/V/T, next PC, memory writes, and elapsed cycles after each instruction.
  4. Only after state matches, re-enable multi-instruction blocks and test IRQ/VBlank, self-modifying code, CPU cache separation, and GBA mode switching.
