## 2. Mission and implementation order

Build a new Wii PowerPC dynamic recompiler inside NooDS-Wii for **both ARM7 (ARMv4T) and ARM9 (ARMv5TE)**. Do not wrap the interpreter in a way that changes guest scheduling or pretends to be native translation. Keep a true interpreter-only build as the reference baseline; the two variants must use the same source and flags except for the JIT enable define (`-DNOODS_JIT=0|1`).

### Phase 1 — 1:1 fallback JIT first

- One eligible guest dispatch maps to one cached native stub. The stub calls a NooDS-Wii helper with the **already fetched opcode**; the helper invokes the existing interpreter handler and returns its real cycle cost.
- The JIT path must not refetch the opcode, advance the guest PC twice, refill the pipeline twice, skip condition handling, or alter scheduler timing. Every state change must match the interpreter.
- Instructions skipped by ARM condition evaluation should remain on the ordinary interpreter fast path. Reserved-condition opcodes and special cases must preserve `handleReserved()` behavior (see §7); do not blanket-ignore every opcode with condition nibble `0xF`.
- This phase is a correctness/wiring baseline and may be slower than interpretation. Keep it green as the oracle for later phases.

### Phase 2 — traces/blocks only after G-1 and Phase 1 gates

Adapt architecture from vbagx, not its whole source. vbagx’s current compiler is **Thumb-only**; it does not solve ARM-state compilation or ARM9. Add NooDS-native block/trace translation incrementally, with interpreter exits for anything not proven correct. Phase 2 must preserve dynamic bus/wait-state/prefetch timing; a static sum of nominal handler costs is not sufficient unless differential tests prove it covers every path.

### 4.3 Verified vbagx facts and critical caveats

These observations were checked in the vbagx clone named in §4.1; line numbers are for that SHA:

- **Scope:** `source/vba/gba/JIT.h:11-18` describes a micro-JIT for GBA **THUMB** runs, explicitly not ARM state. It is a useful Broadway/Wii codegen/cache/SMC reference, not an identical complete solution to NooDS-Wii.
- **Dispatch and length:** `JIT.h:69,110` sets `JIT_TRACE_MAX_INSTRUCTIONS` to 42 and exposes `JITCompileThumbTrace`. `JITCompiler.cpp:105,657-673` compiles a Thumb trace until a terminator or the cap; unsupported opcodes stop compilation (`:2255-2271`).
- **Lookup:** `JITCache.h:113-123` hashes the guest PC with `((pc >> 1) ^ (pc >> 13)) & (HASH_TABLE_SIZE - 1)` and compares the stored `startPC`. `JITCache.cpp:113-168` shows a direct-mapped slot: a colliding block replaces the old slot; there is no chain for hash collisions. This is PC-only because this reference path is Thumb-only and single-CPU.
- **Wii arena:** `Makefile.wii:53-59` defaults `JIT_ARENA_MB` to 16; `JITCache.h:55-61` sizes the Wii arena from that value and uses a 65,536-slot hash table. `JITCache.cpp:89-101` is an aligned bump allocator that flushes the cache on arena exhaustion (`:170-182`). Do not copy stale comments elsewhere in the checkout that say 8 MiB or 512 KiB over the actual Wii Makefile/config.
- **SMC:** `JITCache.h:15-19,61,128-143` and `JITCache.cpp:154-164,261-320` show 65,536 page entries (64 MiB at 1 KiB granularity), byte page flags, and per-page intrusive block lists. The store guard is aimed at GBA EWRAM/IWRAM (banks 2/3), not every address. Invalidation checks code/write overlap, patches the affected block entry to return to the host, marks it non-executable, and unlinks it from the SMC list.
- **Register/flag handling:** `JITCompiler.cpp:249-305` lazily allocates guest R0-R14 to PPC R15-R28 and spills an LRU host register when needed; R29 is PC. `JITPPCEmitter.h:48-90,109-146` is the better current register-map reference: R14 is the GBA register-array base, R30 the read table, and R6 holds packed N/Z/C/V. Flags are loaded/stored lazily but arithmetic flags are computed when the translated instruction updates them; this is not full lazy-flag evaluation. Some `JITTrampoline.S` comments are stale, so cross-check them against the emitter and compiler.
- **Linking:** `JITCache.cpp:192-249` emits a lookup/linker stub that can patch a returning PPC branch directly to a cached target. SMC invalidation patches the target entry so an already-linked edge will bail safely on its next entry.
- **Fallback and cycles:** unsupported code is handed back through the normal C++ Thumb interpreter path (`GBA-thumb.cpp:1377-1495`); it is not a NooDS-style per-instruction `runDecoded()` stub. The compiler carries cycle/prefetch data in `JITResult` and explicit exit code. Study this carefully; do not claim that its fallback ABI or cycle model matches NooDS without a port and tests.
- **I-cache:** `JITCache.cpp:253-257,288-296` uses libogc `DCStoreRange` / `ICInvalidateRange` after generating or patching code. Compare those wrappers with the PPC `dcbst/sync/icbi/sync/isync` sequence used in any NooDS emitter.
- **Performance:** the prior draft’s “180 fps / 25 MIPS vs 5 MIPS / ~5×” was not corroborated in the checked repository. Treat it as an unverified anecdote, not a benchmark or G5 target.

## 7. Interpreter and guest-CPU contracts

These facts were verified in the pinned NooDS base; re-check after refactoring:

- Dispatch tables are `armInstrs[0x1000]` and `thumbInstrs[0x400]` (`NooDS-Wii/interpreter.h:95-98`). `runOpcode()` shifts the pipeline, increments the guest PC by 2 in Thumb or 4 in ARM, fetches the next pipeline word, then dispatches (`interpreter.cpp:224-248`).
- `flushPipeline()` sets the visible PC to instruction address +2 in Thumb or +4 in ARM before refill (`interpreter.cpp:320-331`). Therefore at a normal handler entry the visible `r15` is instruction address +4 in Thumb or +8 in ARM; the base formula is `guestPC = r15 - 2*instruction_size` (Thumb minus 4; ARM minus 8). Verify this at the JIT hook after any pipeline changes.
- ARM condition evaluation precedes the normal handler call. A false condition returns one cycle without calling the handler; condition action 2 invokes `handleReserved()` (`interpreter.cpp:242-245`). **Condition nibble `0xF` is not a blanket “never JIT” rule:** `handleReserved()` routes ARM9 BLX-immediate and special HLE/DLDI opcodes (`interpreter.cpp:424+`). Keep these on the original interpreter path unless deliberately and correctly modeled. Test BLX immediate, BX/BLX register, special HLE return, and reserved/unknown opcodes.
- NooDS’s pinned interpreter already contains ARM9 handlers for CLZ, QADD/QSUB/QDADD/QDSUB, enhanced multiply families, BLX, and CP15 MRC/MCR (`interpreter_lookup.cpp`, `interpreter_alu.cpp`, `interpreter_branch.cpp`, `interpreter_transfer.cpp`). Phase 2 should compile only supported operations or bail to those handlers; do not duplicate or “add” interpreter functionality that is already present. QADD-family saturation uses `clampQ()` and sets CPSR.Q on saturation; SMLA/SMLAW handlers set Q on signed accumulate overflow explicitly. ARM7 paths are architecture-gated.
- CP15 operations change ARM9 system/memory state (`interpreter_transfer.cpp:1167-1186`, `cp15.cpp`). They must always use a correct interpreter fallback until the JIT models the effects.
- `Interpreter` has mixed public/private data members (`interpreter.h:29-105`), so it is not a standard-layout type. Do not rely on `offsetof(Interpreter, private_member)` as portable C++. Expose a narrow friend/accessor/layout helper, derive offsets from a live object with a deliberate design, and assert every generated D-form displacement fits signed 16-bit range. Remember `registers[32]` is a banked pointer table, not one flat guest register array.
- The pinned base has no `runDecoded()` helper; implement/refactor it without changing the existing interpreter dispatch semantics.
- Phase 1 helper contract: accept the already fetched `opcode` and current mode/CPU context; invoke the same interpreter handler exactly once; preserve condition/reserved handling; return the handler’s actual cycle count. Do not refill the pipeline or fetch memory a second time.
- Scheduler timing differs by mode: ARM7 may be advanced at a different rate from ARM9. Preserve the exact `runOpcode()` result and let the existing scheduler remain the authority.
- `Core::endFrame()` stops the run loop and updates host FPS bookkeeping (`core.cpp:349-369`); it does **not** expose the guest cycle count for a frame. Measure guest cycles/state from the interpreter/scheduler and host elapsed ticks separately. The older fixed frame-cycle numbers were not found in the pinned source.
- The headless autoboot described in §9 is **not in the pinned base**. `main.cpp` has an `EmulatorThreadMain` and ROM-loading state, but no `autoboot.txt`, suite-candidate, or rockwrestler-candidate logic. Implement and test it before claiming headless suite readiness.

## 8. JIT design, PPC ABI, and encoding

### Phase 1 cache/pool (proposed; absent from base)

- Proposed starting cache: direct-mapped 8192 entries per CPU, tagged with guest PC/mode/opcode and a nonzero epoch. Verify the tag cannot alias ARM7/ARM9 or ARM/Thumb entries.
- Proposed code pool: a 4 MiB `.bss` word array, shared or carefully partitioned per CPU after measuring Wii MEM1/MEM2 use; initial maximum stub size 160 words. These are design values, not current code.
- On pool wrap, flush every resident stub and bump the epoch. Do not invalidate only the newly written stub while old cache entries can still point into the overwritten range.
- Make emitted code executable coherently. The planned PPC sequence is `dcbst; sync; icbi; sync; isync` for the written range; compare against libogc cache APIs and batch maintenance where safe. The reference uses `DCStoreRange`/`ICInvalidateRange`.

### Phase 2 cache/trace roadmap

- Replace Phase 1’s coarse full-pool wrap behavior with a measured hash-indexed block table and bounded arena. Begin with a conservative per-CPU table or a shared table whose key includes CPU and ISA mode.
- Add an SMC map only over memory that can really be written and executed. NDS7 and NDS9 may share writable memory; invalidation must notify every CPU cache whose translated range overlaps the write.
- Cap trace length, compile latency, and worst-case emitted size. End traces on branches/exceptions/unsupported instructions and any state-changing operation that is not modeled. CP15 always bails for now.
- Arena exhaustion and hash collisions are separate policies. Track hit rate, collision eviction, flushes, and SMC invalidations in `evidence/` before tuning.

### Bridge ABI (to implement and audit)

There is no `jit_bridge.S` in the base. Define an explicit Wii EABI contract before writing assembly:

- For an entry like `jit_enter(void *code, Interpreter *cpu)`, document argument registers, return behavior, stack frame, LR save location, and all caller/callee-saved registers.
- If `r31` holds the `Interpreter*` across emitted code, save and restore the caller’s original `r31`; it is nonvolatile. Preserve every other nonvolatile register the bridge/compiler modifies. Keep `r2`/`r13` ABI-reserved and do not use `r0` as a D-form base.
- Use an explicit common exit thunk and indirect-branch convention (`mtctr`/`bctrl`/`bctr`) with disassembly and call-stack tests. The older 32-byte example omitted a save for `r31`; **do not copy it verbatim**. vbagx’s trampoline saves LR and `r14-r31` in a 128-byte frame (`source/vba/gba/JITTrampoline.S:73-131`), but its ABI is not automatically the correct NooDS ABI.

### Fallback stub and flags

- Planned fallback stub passes the opcode and `Interpreter*` to the C++ helper, returns its real cycles, then exits through the bridge. Keep this as the Phase 2 bail-out tail for unsupported instructions.
- Candidate NZCV mapping for real ALU emission (must be independently verified with the G1 assembler oracle and differential tests):

| Guest flag | PPC source | Intended guest destination |
|---|---|---|
| N (31) | CR0 LT (`mfcr` bit 31) | CPSR bit 31 |
| Z (30) | CR0 EQ (`mfcr` bit 29) | CPSR bit 30 |
| C (29) | XER CA (bit 29) | CPSR bit 29 |
| V (28) | XER OV (bit 30) | CPSR bit 28 |

Harvest CR/XER immediately after the instruction whose result sets them. Preserve flags not written by that instruction. The CPSR Q flag (bit 27) is separate from NZCV and has no ARM7TDMI equivalent; ARM9 saturating/accumulate overflow behavior must match the interpreter.

### PPC encoder traps to verify, not assumptions

- Build and compare every emitted instruction form against devkitPPC assembler/objdump. Keep the namespace `JitPpc`.
- Verify carry/overflow semantics for `addc`/`adde`/`subfc`/`subfe`, branch displacement origin, condition mapping, and zero-shift carry preservation against the architecture and interpreter.
- Branch targets must restore guest PC/pipeline with the same semantics as interpreter branches. Do not truncate guest `r15` to 16 bits.
- Never suppress all `opcode >> 28 == 0xF` instructions: ARM9 BLX-immediate and NooDS special reserved/HLE paths exist. Handle through the interpreter until explicitly supported.

### 9.4 Dolphin headless runner
