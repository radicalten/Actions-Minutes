## Licensing audit and recommendation

This is a repository audit, not a legal opinion. Findings apply to the locally
pinned snapshots in `upstream-lock.json`; they do not assert that the authors have
never granted permission elsewhere.

| Component | Evidence | Release consequence |
|---|---|---|
| mGBA suite auto | MIT text, copyright Jeffrey Pfau, retained in `vendor/mgba-suite-auto/LICENSE` | Retain license and attribution for imported code/tables and derivatives |
| Rockwrestler | No LICENSE/COPYING found in pinned snapshot; README welcomes contributions but supplies no explicit redistribution license | Blocking: permission must cover source, modifications, generated/linked ROM and assets |
| Original project work | MIT approved by user; root LICENSE added | Applies to original project contributions only |
| Fonts/assets and adapted startup/linker code | Build currently depends on upstream framework; ownership/permissions need explicit review | Do not assume a source-code permission automatically clears every asset |
| Toolchain/emulator dependencies | Installed separately, not bundled | Document versions and licenses; audit runtime/linker dependencies of ROM |
| Nintendo BIOS/firmware | Not to be distributed | Never include in repository or release |

**Approved:** MIT for original project work, as authorized by the user, because
it is simple and compatible with the retained mGBA MIT material. Do not apply a
blanket MIT license to the current combined tree. Rockwrestler permission is the
blocking dependency. Preferred route: obtain an explicit upstream license or
written redistribution grant covering all included material. An alternative is
an independently implemented replacement with a documented provenance review;
that would require substantial development and validation. Removing a LICENSE
warning or changing attribution does not solve the issue. An upstream-download
script is not a substitute for permission to distribute the combined ROM.

## Work order

1. Continue the finite coverage ledger: Thumb literal/PC/SP/high-register forms,
   branch boundaries and stack/multiple-transfer edges; then remaining memory,
   encoding, CPU-specific/system and source-port work. Do not call a representative
   operand matrix exhaustive. Exact ARM7 and hardware-oracle limits need an explicit
   resolution, not an implied pass.
2. Resolve licensing in parallel, before assembling publicly redistributable files.
3. Migrate historical fixed-count regressions and package guards to current
   manifest/protocol contracts; refresh the full current-ROM evidence set.
4. Implement and test clean-checkout dependency setup, deterministic build and CI.
   Host tests must not depend on a private workspace or deleted historical reports.
5. Prepare root documentation, contribution/security guidance, changelog, issue
   templates, license notices and dependency inventory. CI must not equate known
   emulator discrepancies with harness failure or hide them by blanket exit overrides.
6. Assemble and test `v1.0/` from an explicit allowlist. The **contents** of that
   folder become the repository root, including `.github/` and `.gitignore`.
   No account-specific owner/repository values should be required just to build.

## Upload-ready folder contract

Include the ROM, complete permitted source/vendor dependencies, generators,
regression scripts and fixtures, lock/version records, build instructions,
agent-readable schemas, remaining-scope disclosures, known failures and selected
current evidence. Include `SHA256SUMS` and `RELEASE.json` linking ROM/source/evidence
identity. Avoid recursive hashing of the checksum file itself. Diagnostic blob
paths must be portable relative paths and all referenced blobs must be included.

Exclude local virtualenvs, nested `.git`, credentials, caches, core dumps, obsolete
archives, unnecessary upstream binaries/disassembly and unneeded build outputs.
An explicit file/secret/size audit is required. No tools or copyrighted BIOS files
are bundled. Validate the copied folder in a fresh directory with no workspace
fallback, run all release gates, then create the replacement archive and retain
only the latest verified one. Do not merely rename the current development tree.

The existing `scripts/package.py` remains a historical milestone10 packager and
must not be used to stamp v1.0. No release date is promised until coverage,
licensing and validation blockers are cleared.
